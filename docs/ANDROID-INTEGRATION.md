# ربط تطبيق AIM8 Android بخادم الموقع

**الحالة:** خادم موقع AIM8 جاهز لاستقبال طلبات الجهاز؛ **تطبيق Android نفسه لم يُعدّل**، ويجب دمج هذه الخطوات في كود Kotlin الخاص به قبل الاعتماد على قفل الحساب.

## قاعدة الجهاز الواحد

- جميع الأجهزة يمكن أن تفتح موقع الشراء والدخول بالمتصفح؛ هذا **لا** يحجز خانة الجهاز.
- أول تطبيق Android يفعّل الحساب يخزن زوج مفاتيح ECDSA P-256: `private key` داخل `AndroidKeyStore` (غير قابل للتصدير حسب خصائص المخزن) و`public key` يرسل للسيرفر.
- إذا استلم السيرفر مفتاحًا عامًا مختلفًا بعد التفعيل، يعيد `409 DEVICE_ALREADY_BOUND` و**لا** يلغي حق الجهاز الأول.
- المالك يستطيع فك الارتباط فقط من `/admin.html`، وبعدها يستطيع المستخدم تفعيل جهاز جديد.
- المعرّفات مثل Android ID أو IP ليست مصدر الثقة، بل إثبات امتلاك مفتاح التوقيع المحفوظ على الجهاز.

## واجهات API

جميع العناوين تحت `https://aim8.site/api` وتستخدم JSON (ما عدا HMAC الخاص بدفعات OxaPay).

1. `POST /device/login` — `{ "email": "...", "password": "..." }`. يرجع `activationToken` مدته 300 ثانية **إذا كان الاشتراك نشطًا**.
2. `POST /device/challenge` — `{ "email": "..." }`. يرجع `challengeId` و`nonce`، صلاحية 120 ثانية.
3. لتفعيل الجهاز لأول مرة: وقّع النص UTF-8 **الحرفي** `AIM8:activate:<challengeId>:<nonce>` باستخدام مفتاح الجهاز الخاص؛ أرسل `POST /device/activate`:

   ```json
   {
     "challengeId": "...",
     "publicKey": "BASE64URL_DER_SPKI_PUBLIC_KEY",
     "signature": "BASE64URL_64_BYTE_IEEE_P1363_SIGNATURE"
   }
   ```

   مع `Authorization: Bearer <activationToken>`. لا تضع الرمز في رابط URL.
4. في كل تشغيل أو فترة تحقق معقولة: `POST /device/challenge`، ووقّع `AIM8:verify:<challengeId>:<nonce>`، ثم أرسل `POST /device/verify`:

   ```json
   {"email":"...","challengeId":"...","signature":"BASE64URL_P1363_SIGNATURE"}
   ```

   يرجع `deviceAccepted`, `subscriptionActive`, `subscriptionUntil`, `serverTime`. **لا تُفعّل الخطوط عندما يكون `deviceAccepted` أو `subscriptionActive` ليس true.**

## صيغة التوقيع — مهمة جدًا

- الخوارزمية في الخادم: `ECDSA P-256 + SHA-256` مع تمثيل التوقيع **IEEE P1363** (`r` 32 bytes ثم `s` 32 bytes، الإجمالي 64 بايت).
- `java.security.Signature("SHA256withECDSA")` في Android عادة يرجع **ASN.1/DER** وليس P1363. **حوّل التوقيع من DER إلى P1363** قبل إرساله أو اختر موفرًا يدعم P1363 بصورة صحيحة. لا ترسل DER مباشرة لأنه سيرفض.
- المفتاح العام يكون بصيغة DER SubjectPublicKeyInfo (SPKI)، صادر من `keyPair.public.encoded`، ومُرمّز Base64 URL Safe بدون padding.
- احتفظ بالمفتاح الخاص داخل Android Keystore فقط. تجنب أي مفتاح جهاز قابل للاستخراج أو محفوظ في SharedPreferences.

## ملاحظة أداء مهمة

لا تنفّذ استعلام التحقق مع كل إطار رسوم أو كل 0.5 ثانية. فحوصات التراخيص المنفصلة قد تكون عند فتح التطبيق ودوريًا كل ساعات بحسب سياسة المنتج وقيود D1، بعيدًا عن معالجة كشف الكرات ومعدل FPS. وإذا رغبت بدعم انقطاع الإنترنت، حدّد سياسة فترة سماح قصيرة بعد آخر تحقق ناجح، مع العلم أنها تُضعف قدرة الإيقاف الفوري.

## مستوى الحماية

هذه الآلية تمنع الجهاز الثاني عند التحقق من السيرفر، لكن لا يمكن ضمان منع النسخ/التحايل على جهاز معدل بنسبة 100%. يمكن إضافة Play Integrity وفحص سلامة الحزمة مستقبلاً. تغيير الجهاز يحتاج قرار دعم يدوي، ولا يحدث تلقائيًا بناءً على كلمة المرور وحدها.
